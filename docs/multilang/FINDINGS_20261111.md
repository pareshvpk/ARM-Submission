Experiment copy only. Measured = run on this machine today; file names give the evidence.

## 2. Restoring the full vocabulary does not fix native scripts by itself (measured)

`bench/heldout_ml/score_arms.py` -> `docs/multilang/arms_20261111.md/.json`. Same v5 weights, PyTorch fp32, shipped
fusion. Arm P applies the shipped `id_map.json`; arm U uses the full embedding table.

English and Hinglish levels are identical between the two arms (0 changes), as they must be.

| Slice | n | Pruned (shipped): recall / false alarms | Unpruned: recall / false alarms |
|---|---|---|---|
| Overall | 13,098 | 0.765 / 11.1 % | 0.886 / 25.1 % |
| English | 1,209 | 0.935 / 0.5 % | 0.935 / 0.5 % |
| Hinglish | 1,000 | 0.932 / 0.0 % | 0.932 / 0.0 % |
| Tamil | 454 | 0.940 / 31.2 % | 0.945 / 38.6 % |
| Hindi | 1,000 | 0.964 / 12.8 % | 0.952 / 10.4 % |

Golden set (hand-written, not yet checked by the owner): pruned 56 of 60 Tamil and 58 of 60 Hindi; unpruned 59 of
60 and 58 of 60. All six phone test messages are right in both arms.

Reading:
- With the full vocabulary the model catches many more native-script scams (overall recall +12 points) and also
  flags many more genuine messages (false alarms +14 points). It behaves as if "native script" itself were a risk
  signal. That matches the training data: the corpus has native-script spam and scam but little native-script
  genuine text.
- So pruning hides part of the problem rather than causing it. Arm U fails the acceptance rule (Tamil false alarms
  38.6 %, limit 5 %). Keeping script tokens at export is necessary for any fine-tuned model, but is not a fix on
  its own and must not be ported to the original project as one.
- The golden set is easier than the synthetic held-out set: both arms already clear its 54-of-60 line. It cannot
  by itself show an improvement; the Tamil and Hindi held-out false-alarm lines carry the decision.

## 3. What the false alarms are (read by the manager, `data/tools/show_heldout_false_alarms.py`)

Tamil: 84 of 272 genuine held-out rows are flagged. The sampled ones are bank credit alerts ("ரூ. 1089 வரவு
வைக்கப்பட்டுள்ளது ... இருப்பு ரூ. 39390") and gas-cylinder booking confirmations, scored `unwanted` 0.98 to 1.00,
which lands at medium. Electricity-payment confirmations and personal messages in the same set stay low.

Hindi: 64 of 500 are flagged. The sampled ones are credit-card statement notices, an EMI auto-debit notice and a
mobile bill reminder, scored `scam` 0.92 to 1.00.

These are transactional messages, the most common genuine SMS a user receives. The data added for training must
therefore contain native-script transactional ham. The translation sampler prefers rows with Indian banking
markers for that reason, and the `nikhil7g` Hindi set is mostly bank alerts.

Caveat: the held-out rows are synthetic templates (63 distinct openings among the 84 flagged Tamil rows, many
differing only in the amount), so each template counts many times.
