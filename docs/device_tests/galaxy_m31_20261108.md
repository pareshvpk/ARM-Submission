# Device test: Samsung Galaxy M31 (SM-M315F) (2026-11-08)

Device: Exynos 9611 (4x Cortex-A73 2.31 GHz, CPU part 0xd09, + 4x Cortex-A53 1.74 GHz, 0xd03), 5.4 GiB RAM
(MemTotal 5706212 kB), Android 12 (API 31). CPU features: fp asimd evtstrm aes pmull sha1 sha2 crc32 cpuid,
that is **Armv8.0: no atomics (LSE), no dot product, no fp16**. APK: debug build of commit ba44b2b; seven model
files pushed after a first launch, SHA-256 checked on the phone.

Scope rule as in [moto_g73_20261108.md](moto_g73_20261108.md). At the end the app was uninstalled, the leftover
checks found nothing, and Samsung's crash dialog for the app was dismissed with Back. System crash records
(tombstones, dropbox) written by Android for the crashes cannot be removed without root; they are system-owned
and rotate out on their own.

## Results

| Step | Result |
|---|---|

| User-visible | App closes; Samsung shows "PS3 Sentinel closed because this app has a bug" |

No message could be analysed. The prebuilt ExecuTorch native library uses instructions that Armv8.0 cores do
not have, and the app has no CPU feature check before loading a model (`ExecutorchGate` is only a thread lock).
The same crash would happen in `SmsReceiver` on every incoming SMS. Tracked as DT-9 in [PROBLEMS.md](PROBLEMS.md).
